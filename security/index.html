CRYPTOGRAPHIC TRUST CENTER

Security & Hardening Architecture

Defense-grade security by design. Cryptographic proof of origin, sandboxed execution boundaries, and zero cloud telemetry dependencies.

Last Updated: October 10, 2026 • Standard Version v2.5.0 • J AI ENTERPRISES
SUMMARY IN PLAIN ENGLISH
  • ✓ Your documents never leave your machine unless you explicitly configure remote relays.
  • ✓ Every block is cryptographically hashed with SHA-256 and signed with Ed25519 / ECDSA keys.
  • ✓ Executable JavaScript and reactive formulas run in isolated sandboxed iframes with zero parent DOM access.
SECURITY DEFENSE-IN-DEPTH ARCHITECTURE

Three Isolated Protection Boundaries

LAYER 1 • NETWORK BOUNDARY
100% Air-Gapped & Sovereign Egress Guard
Zero telemetry beacons. All 3D runtimes, math engines, and font metrics are bundled locally. Runs fully disconnected in secure air-gapped SCIF facilities.
LAYER 2 • RUNTIME ISOLATION
Zero-Privilege Sandboxed Execution Boundary
Raw eval() and new Function() strictly banned. Interactive charts, React widgets, and WebGL scenes execute in isolated <iframe sandbox> via sanitized postMessage RPC.
LAYER 3 • CRYPTOGRAPHIC PROVENANCE
Merkle SHA-256 Tree & Ed25519 Root Seal
Every block, paragraph, and 3D mesh is hashed into a cryptographic Merkle tree. Bit-level modifications trigger an instant integrity alarm in <15ms.

01. Cryptographic Merkle SHA-256 & Ed25519 Signing

Every living document created or compiled with LDOC Studio is sealed with a deterministic SHA-256 Merkle Tree and Ed25519 digital signature manifest:

  • Upon document compilation, the manifest metadata and block payloads are individually digested using SHA-256.
  • The root digest is signed by the author's private key, producing an authentic signature saved to signatures/ed25519.sig.
  • The author's public key is bundled in JSON Web Key (JWK) format at signatures/public-key.jwk.
  • Upon opening, local integrity validation computes the verification locally, raising an alarm in <15ms if even a single character or mesh coordinate is tampered with.

02. Zero-Privilege Sandboxed Runtime Isolation

Dynamic living documents execute user-provided code, interactive charts, and WebGL models. To prevent arbitrary code execution vulnerabilities:

  • Raw new Function() and eval() are completely banned across all runtime parsers and viewers.
  • All JavaScript widgets, React JSX blocks, and Chart.js code execute inside origin-isolated <iframe sandbox="allow-scripts"> elements.
  • The iframe is strictly isolated from parent DOM trees, localStorage, cookies, and tokens, communicating solely through sanitized postMessage RPC protocols.

03. Native Desktop Chromium Hardening

In the standalone desktop application, security controls are enforced at the native Chromium level:

  • webSecurity: true is enforced to uphold standard Same-Origin Policy.
  • nodeIntegration: false guarantees renderer processes cannot access Node.js APIs or native OS shell paths directly.
  • contextIsolation: true prevents prototype pollution between web content and preload scripts.
  • allowRunningInsecureContent: false blocks mixed-content network attempts.

04. Air-Gapped & Sovereign Network Compliance

LDOC Studio and the standalone mobile APK are engineered to operate in 100% air-gapped environments (SCIF, shipboard, military, nuclear, and financial server rooms). All vendor scripts (Three.js, Chart.js, OrbitControls, GLTFLoader) are bundled locally. The application never requires an internet handshake to view, edit, or sign documents.
