SPEC-01 • CONTAINER ARCHITECTURE

1. The .ldocx Dual-Container

An .ldocx file is a standard deterministic ZIP archive holding machine-evaluable AST descriptors, compressed spatial CAD meshes, and cryptographic provenance trees. It implements dual-container backward compatibility for seamless migration across 20-year archival lifespans.

Component File Standard Level Purpose & Lifecycle
manifest.json Canonical v3.0 Document metadata, engine targets, hardware attributes, and root hashes.
document.json Canonical v3.0 The modern semantic AST node hierarchy and reactive formula graph.
spec.json Legacy v2.0/v2.5 Maintained for backward-compatible rendering in earlier studio versions.
fallback.html Archival 20-Yr Self-contained, zero-dependency offline web presentation for universal access.
SPEC-02 • SEMANTIC AST

2. Deterministic AST & Reactive DAG

Document nodes represent discrete semantic blocks. Reactive blocks establish explicit input dependencies, evaluated as a Directed Acyclic Graph (DAG) with topological sorting. This mathematical model guarantees zero circular dependency locks and eliminates visual glitch flickers.

REACTIVE FORMULA EVALUATION ENGINE
DAG: $slider.torque (340 Nm) ──▶ f(t) = t * 0.126 ──▶ #thermal-val (+42.8 °C)

All text measurement and line-breaking algorithms are executed mathematically through LdocTextLayout without DOM geometry reads, preventing forced layout thrashing across slides.

SPEC-03 • SPATIAL 3D MESH

3. Draco 3D Geometry Pipeline

Spatial 3D blocks embed Google Draco compressed geometry buffers directly within the assets/meshes/ container partition. Heavy mechanical CAD assemblies and robotics kinematics achieve up to 92% compression ratio while retaining discrete 60 FPS client rendering.

SPEC-04 • CRYPTOGRAPHIC PROVENANCE

4. Merkle Tree & Signatures

Every constituent block in the document is hashed into an Ed25519-signed Merkle Tree (merkle.proof). Authors sign the root hash digest using their hardware cryptographic key. Readers independently verify bit-level integrity with zero third-party notary roundtrips.

SPEC-05 • ARCHITECTURAL INVARIANT

5. Export Flattener Parity

The foundational invariant of the LDOC living document architecture is Zero Text Drift Across Surfaces. The interactive Editor, the Viewer, and the headless PDF flattener evaluate line-breaks, line counts, and bounding heights using the identical mathematical model.
